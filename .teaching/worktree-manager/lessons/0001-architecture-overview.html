1. 为什么需要 WorktreeManager？

Sandcastle 需要让 AI Agent 在一个 隔离环境 中编写代码。最直接的隔离方式是 git worktree——让 Agent 在独立的工作目录中操作自己的分支，不打扰开发者的主工作区。

关键约束：Git 不允许同一个分支同时在两个 worktree 中 checkout。这个限制贯穿了整个模块的碰撞检测逻辑。

3. 关键设计决策一览

这个模块背后有两个重要的 ADR（架构决策记录），理解它们是读懂代码的前提：

ADR 0003：默认复用 worktree

当用户重新运行相同命令时，不再报错。而是：

Worktree 状态行为代码位置
Clean + 落后于 origin快进同步 (--ff-only)fastForwardFromOrigin() L213
Clean + 已是最新直接复用，打印日志create() L346
Dirty（有未提交修改）复用 + 发出警告create() L341
Diverged（有未推送提交）保持不动，复用fastForwardFromOrigin() L256
核心原则：永远不用 git reset --hard。--ff-only 保证只在本地严格落后于远端时才移动 HEAD——不会丢失任何工作。

ADR 0018：分支名需要随机后缀

generateTempBranchName() 在时间戳后附加 6 字符的随机十六进制后缀。原因：并发调用 run() 或 fork() 可能在同一秒内执行，仅靠秒级时间戳会碰撞。

// L82-89
export const generateTempBranchName = (name?: string): string => {
  const ts = formatTimestamp(new Date());
  const suffix = randomBranchSuffix();  // 3 字节 = 6 位 hex
  if (name) {
    return `sandcastle/${sanitizeName(name)}/${ts}-${suffix}`;
  }
  return `sandcastle/${ts}-${suffix}`;
};

4. Effect-TS 在本模块中的角色

如果你不熟悉 Effect-TS，只需要理解 3 个模式就能读懂整个模块：

Effect.async — 把 Node.js 回调变成 Effect

execGit() 是唯一的 Effect.async 使用点。它把 child_process.execFile 的回调包装成 Effect<string, WorktreeError>：

const execGit = (args, cwd) =>
  Effect.async((resume) => {
    execFile("git", args, { cwd, env }, (error, stdout, stderr) => {
      if (error) {
        resume(Effect.fail(new WorktreeError({ ... })));
      } else {
        resume(Effect.succeed(stdout));
      }
    });
  });

📌 resume 必须且只能调用一次。传入 Effect.succeed 表示成功，Effect.fail 表示失败。

Effect.gen — 用 generator 写顺序逻辑

create()、fastForwardFromOrigin()、pruneStale() 全部用 Effect.gen(function* () { ... })。yield* 相当于 await——等待一个 Effect 完成：

Effect.gen(function* () {
  const fs = yield* FileSystem.FileSystem;  // 获取依赖
  const existing = yield* listWorktrees(repoDir);  // 等待 git 结果
  // ... 同步风格的顺序逻辑
});
Effect.catchAll / catchSome / either — 错误处理

三种模式在本模块都有使用：

  • catchAll — 捕获所有错误并转换（L367: invalid reference 时降级为 -b 创建新分支）
  • catchSome — 只捕获特定错误（L479: 只处理 NotFound，其他错误继续传播）
  • either — 不抛出，返回 Left(error) | Right(value)（L234, L250: fetch/merge 失败时走降级路径而非抛出）

6. 调用者是谁？

整个 sandcastle 中有 4 个文件导入 WorktreeManager：

调用者用法
createSandbox.ts创建沙箱时创建/复用/清理 worktree
SandboxFactory.ts工厂模式中协调 worktree 生命周期
createWorktree.ts公开的 createWorktree() API
interactive.ts交互模式中管理 worktree
run.ts仅导入工具函数（generateTempBranchName, getCurrentBranch）
模式：所有调用者都遵循相同的三步流程：pruneStale() → create() → 使用 → remove()（或保留 worktree 供下次复用）。

🧪 快速检验

当一个 clean 且有未推送提交 的 worktree 被 create() 再次命中时，Sandcastle 会怎么做？

  • 执行 git reset --hard origin/branch 覆盖本地
  • 抛出 WorktreeError 拒绝使用该目录
  • 尝试快进失败后直接复用，保留未推送提交
  • 删除旧 worktree 后重新创建全新工作目录

🧪 快速检验

NO_CONFIG_LOCK_FLAGS 解决的是什么问题？

  • 防止 Agent 修改仓库的远端地址配置
  • 防止 git 写入追踪配置导致 .git/config.lock 竞争
  • 禁用 worktree 的自动垃圾回收以提升性能
  • 阻止 git push 操作以保护 origin 分支安全

🧪 快速检验

execGit() 为什么要设置 LC_ALL: "C"？

  • 让 git 输出更短的错误信息以节省内存空间
  • 确保 git 使用 UTF-8 编码处理中文文件路径
  • 强制英文输出，使 stderr 匹配逻辑不受本地化影响
  • 兼容 Windows 环境下不同的默认字符编码设置
