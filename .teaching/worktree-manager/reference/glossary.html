术语表

📖 WorktreeManager.ts 核心术语速查

术语含义出处
Worktree Git worktree——在 .sandcastle/worktrees/ 下创建的隔离工作目录。共享主仓库的 Object 数据库和 Refs，但有独立的 HEAD 和 index。 Git 文档
Branch strategy Sandcastle 控制 Agent 代码如何关联分支的策略。三种：head（直接用主目录）、merge-to-head（临时分支 → 合回 HEAD）、branch（指定分支名）。 CONTEXT.md
Source branch Agent 实际工作的分支（由 branch strategy 决定）。 CONTEXT.md
Target branch 调用 run() 时 Host 的当前分支——merge-to-head 策略的合并目标。 CONTEXT.md
Managed worktree 路径在 .sandcastle/worktrees/ 下的 worktree，由 Sandcastle 创建和管理。对比"外部 worktree"（用户自己创建的）。 代码 L141
Collision / 碰撞 目标分支已被某个 worktree checkout 的情况。Git 禁止同一分支在两个 worktree 同时 checkout。 代码 L128
Fast-forward git merge --ff-only——只在本地严格落后于远端时移动 HEAD。不会创建 merge commit，不会覆盖本地工作。 ADR 0003
Orphaned worktree .sandcastle/worktrees/ 下存在目录，但 git worktree list 中没有对应条目——已被 git 遗忘的残留目录。 代码 L153
NO_CONFIG_LOCK_FLAGS -c branch.autoSetupMerge=false -c push.autoSetupRemote=false。防止 git worktree add -b 因用户全局配置而写入 .git/config，避免 lock 竞争。 代码 L16
Effect.gen Effect-TS 的 generator 语法。yield* 等同于 await，用于顺序编排异步操作。 Effect 文档
Effect.async 把回调式 API 转成 Effect。resume(Effect.succeed(v)) 或 resume(Effect.fail(e))，只调用一次。 Effect 文档
Data.TaggedError Effect 的结构化错误基类。WorktreeError 和 WorktreeTimeoutError 均基于此，通过 _tag 字段实现类型安全的错误匹配。 代码 L39, L80 (errors.ts)
Sandbox provider 可插拔的沙箱实现。三种：bind-mount（Docker 挂载）、isolated（远端环境 + sync）、none（直接跑在 host）。由 tag 字段区分。 CONTEXT.md
acquireUseRelease Effect 的资源管理模式（类似 try-finally）。acquire 获取资源，use 使用它，release 无论成功失败都执行。SandboxFactory 用双层嵌套管理 worktree（外层）和 sandbox handle（内层）。 SandboxFactory L594
cleanupWorktree release 阶段函数。dirty worktree 保留（打印路径），clean worktree 删除。返回保留路径供 attachPreservedPath 使用。 SandboxFactory L203
attachPreservedPath 把保留的 worktree 路径附着到 AgentError / AgentIdleTimeoutError 的 preservedWorktreePath 属性上，让程序化调用方能从错误对象中获取路径。 SandboxFactory L232
resolveGitMounts 解析 .git 的挂载需求。普通仓库只挂 .git/ 目录；worktree 需额外挂父仓库的 .git/（因为 worktree 的 .git 只是一个 gitdir 指针文件）。 SandboxFactory L264
